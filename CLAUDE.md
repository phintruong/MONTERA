# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An interactive 3D step player for assembling IKEA flat-pack furniture: 3 hand-made LACK guides plus 118 generated ones, phone-first. It is built for a user study comparing it against the paper manual. Vite + React 19 + TypeScript, react-three-fiber/drei for 3D, zustand for state, Tailwind v4, zod for data validation. `PRODUCT.md` (users, principles) and `DESIGN.md` (colour/type tokens, the manual line-drawing look) are the source of truth for UX and visual decisions. Read them before UI work.

## Commands

```
npm run dev                                  # http://localhost:5173
npm run build                                # tsc -b && vite build
npm run lint                                 # oxlint (.oxlintrc.json)
npm test                                     # vitest run (src/engine/pose.test.ts: side table; products.test.ts: every product)
npx vitest run -t "explode"                  # run a single test by name
node scripts/asm-stats.mjs                   # IKEA ASM annotations -> src/data/asm/<product>.json
node scripts/gen-lack.mjs                    # regenerate src/data/lack.json
node scripts/gen-lack-shelf.mjs              # regenerate src/data/lack-coffee.json and lack-tv.json
node scripts/import-ikea-manual.mjs          # IKEA-Manual meshes -> public/products/im-*.json + src/data/catalog.json
node scripts/gen-flatpack.mjs                # simplified KALLAX/BILLY/EKET/LINNMON -> public/products/fp-*.json + src/data/catalog-flatpack.json
node scripts/analyze-study.mjs study-logs/   # exported study logs -> study-results/sessions.csv + steps.csv
```

**Generated products.** Besides the 3 bundled LACK guides, `public/products/*.json` are fetched on demand (`loadProduct`). `im-*` come from the IKEA-Manual dataset (run `scripts/extract-ikea-manual.py` with a Python that has pyarrow + numpy first; approximate scale, fittings not shown). `fp-*` are box models built from nominal outside sizes with a generic build order: cases are built lying on their front, then stood up with one rigid turn about the bottom-front edge. `products.test.ts` checks every generated file (flat-pack ones: no box corner below the floor at any time, upright at the end). The header picker is a search box over all of them (accents folded, so "poang" finds POÄNG).

**Hands.** Removed for good (models, `handAt`, the step `hands` field). Don't reintroduce them.

**Layout and phones.** Phone portrait is the primary layout. `src/index.css` defines three custom variants:
- `side:` 3D view and panel side by side (width ≥ 768 px, or a phone held sideways). Use it, not `md:`, for layout.
- `short:` height ≤ 540 px.
- `roomy:` big screens; the only place type may grow.

Step controls are pinned at the panel's foot. `src/ui/mobile.ts` has swipe-to-step, the screen wake lock and the step-change buzz. Respect `env(safe-area-inset-*)` on anything at a screen edge. Step cameras are framed for landscape; `CameraRig` pulls back on portrait canvases.

## Architecture

**Data-driven assembly.** Each product is described by one JSON file, `src/data/<product>.json`, generated by a `scripts/gen-*.mjs`. Edit the script, not the JSON, or your changes are lost on the next regen. `src/data/products.ts` is the registry. One product is loaded per page via `?product=`, and the header picker reloads with a new one. `api/ask.ts` imports the bundled guides itself (JSON import attributes), so add new bundled products in both places. It reads generated ones from `public/products/`, which `vercel.json` ships with the function via `includeFiles`. `gen-lack-shelf.mjs` tips the table onto its sides for the bracket steps. It tracks the body's rigid transform the same way the engine replays `rigid` moves, so new parts are placed at body-transform × their spot on the table. Move parts by changing that local spot, not by hard-coding world coordinates. `src/data/schema.ts` defines it with zod: `parts` (shapes/sizes), `instances` (placed copies of parts with an initial pose and `enterStep`), and `steps`. Each step has `moves` (absolute `to` moves with optional `spin`, or `rigid` group rotations about a pivot, timed by `start`/`end` within 0..1 of the step), plus camera, active parts, arrows, a tray, a checklist and FAQ entries. `parseAssembly` also checks referential integrity. Units are **mm and degrees**; the scene converts to metres.

**Real-world timing.** `scripts/asm-stats.mjs` reads the IKEA ASM dataset's action labels (about 95 recorded builds per LACK product). It maps ASM action labels to step ids in `PRODUCTS` and writes `src/data/asm/<product>.json`. `scripts/lib/asm.mjs` (`mergeAsm`) merges that into `step.typical`, adds "how long" FAQ entries, and sets `assembly.sources`. Typical time shows in the step header, the `/api/ask` context, and the study export `baseline`. Steps with no ASM equivalent (screws, brackets, wall anchor) have no `typical`. The dataset is CC BY-NC 4.0: commit only derived stats, never the raw `datasets/` folder. ASM's fourth product, the KALLAX drawer, was left out on purpose: the current IKEA manual (AA-1009361) differs from the recorded version.

**Pure pose engine.** `src/engine/pose.ts` is the core: what's on screen is a pure function of `(step, t)`. `frameAt` replays all previous steps' moves to t=1, then the current step's moves at `t`. That gives continuity: the end of step N equals the start of step N+1, and the tests rely on it. `explode` derives from a frame. Keep rendering code (`src/scene/`) free of animation state. Change behaviour in the engine/data and cover it in `pose.test.ts`.

**State.** `src/store.ts` holds the parsed `assembly` singleton and a zustand store for `step`, `t`, play/explode, per-step checklist ticks (Next is blocked until the checklist is complete), true-size calibration (`pxPerMm`, stored in localStorage), and an event log. Every user action goes through `record(type, data)`. The log is study data: when adding actions, keep passing the `how` argument (e.g. `'voice'`), which records how the user triggered them.

**Study mode.** `?study=1&cond=app&pid=P01&product=lack` shows a timer and log export (`exportLog` downloads JSON) and hides the product search. `cond=paper` renders `src/ui/PaperStudy.tsx` instead: an experimenter screen with no 3D, which writes the same log format (`step_enter`/`finish` plus `stuck`/`error`/`help` observations). Keep the two log formats compatible with `scripts/analyze-study.mjs`. Participant logs live in the gitignored `study-logs/` and `study-results/`.

**Ask / voice.** `src/voice/` uses the browser Web Speech API (Chrome). `parseCommand` maps utterances to commands (next/back/again/done/explode/pause/ask). `src/ask/ask.ts` POSTs to `/api/ask` and falls back to the per-step offline FAQ (`src/ask/faq.ts`) when the call fails. `api/ask.ts` is a Vercel Function that uses the AI SDK through AI Gateway (`anthropic/claude-haiku-5-5`). It only gets the current product's current step as context. `npm run dev` doesn't serve `/api`, so locally you only get FAQ answers unless you run it with `vercel dev`.

**Assets.** LACK and flat-pack parts are procedural primitives (`box`/`cylinder`/`screw`). The IKEA-Manual guides carry their own triangle meshes (`shape: 'mesh'`) with precomputed outline edges. Part letters (`instance.label`) are DOM tags positioned each frame by `Parts`, not drei `<Html>`, which dropped the first of many labels under React 19.
